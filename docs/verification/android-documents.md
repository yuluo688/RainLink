# Android 系统文件保存

日期：2026-10-17。Android 使用系统文件保存器选择导出位置，适用于连接、日志、流量 CSV 及受控高级配置 YAML / JSON。没有申请广泛存储权限。

## 保存路径

1. Flutter 在应用缓存内为本次导出生成独立临时文件。方法通道只传文件路径、建议名称、MIME 和请求 ID，不经平台通道复制大段内容。
2. 原生校验来源的规范路径、请求 ID、扩展名与 MIME、文件名称及大小。只能读取本次导出目录内的 `content` 文件，不能传任意应用文件。
3. `ACTION_CREATE_DOCUMENT` 由用户选择位置。后台线程将内容写入系统返回的文档，等待写入、flush 和 close 完成后才返回真实 `content://` URI。
4. 用户取消返回空结果，页面不显示导出成功。失败返回可见错误；如果覆盖已有文档时写入失败，提示检查不完整文件，不自动删除用户原文件。
5. 同时只允许一个系统保存请求。超时取消使用本次请求 ID，不影响其他请求；不同请求使用不同 Activity 请求码，迟到的旧回调不能完成新请求。Activity 销毁时取消待处理导出，Flutter 最终删除临时内容。

## 验收

隔离的 Android 16 x86_64 `RainLink_QA` 模拟器通过真实系统选择器创建 CSV，再通过 ContentResolver 读回并逐字节核对 UTF-8 内容和文件名。测试随后取消第二次保存，确认返回空结果。

另一项原生用例拒绝非法来源、路径、MIME、请求 ID 和类型，检查重复保存、无关请求取消，以及选择器仍打开时关闭 Activity 的取消回执。用例只删除自己刚创建的唯一 QA 文档，不接触用户文件。完整结果见 [原生记录](android/instrumentation.txt)及[机器结果](android/native-evidence.json)。

两项保存用例另有[独立专项记录](android/document-instrumentation.txt)。自动化同时读取活动窗口和交互窗口，避免文件名键盘或页面切换遮住选择器的无障碍节点；以单调时钟限制等待，超时保存现场截图并保持测试失败。

Flutter 的 10 项业务回归覆盖实际临时文件字节、取消、无效回执、原生错误、超时取消和输入限制，均检查临时文件释放。

[Flutter 实际核心界面测试](android/flutter-telemetry-evidence.json)显式使用应用私有导出器，检查连接及日志 CSV 的真实内容。它没有自动操作系统选择器；系统保存的证据由上述独立原生测试提供。

## 边界

已验证本模拟器系统文档提供器，不代表所有云盘或厂商文件提供器都已验收。系统分享入口尚未接入；这里提供的是可选择位置的文件保存。进程被系统直接终止时不会伪造成功回执，系统目标可能留下不完整文件。

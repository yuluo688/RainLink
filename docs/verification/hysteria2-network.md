# Hysteria2 真实网络续验

2026-10-16，Windows x64；核心仍为 sing-box 1.12.25-rainlink.1，核心与证书扩展没有重新修改。

## 本次结论

已取得真实机场 Hysteria2 的 HTTPS 传输、真实出口和上传下载计数，Windows Release 窗口也取得台湾线路实际出口并记录流量。不能再将首次的全部握手超时作为当前唯一结论；也不能据几次成功认定全部线路稳定。多轮请求仍存在间歇超时。

最初本机 FlClash TUN 正在运行，默认路由包含该 TUN，部分节点域名被系统解析为 `198.18.0.0/15` Fake-IP。对两条 IP 字面节点做默认路径与显式物理接口对照，后者完成 HTTPS 204 请求；对域名的对照中，同一网卡上的独立 HTTPS 解析也取得成功。随后用户关闭 FlClash；经进程和路由确认退出后继续测试，没有重新开启或更改它的配置。

## 代码改动

- Windows Hysteria2 的公网上游按活动非隧道默认路由选择网卡，比较路由与接口的总 metric，明确排除回环和 TUN / tunnel 类型；处理 IPv4 / IPv6、相同 metric 的确定顺序及加法溢出。接口名称来自当前系统，没有硬编码本机名称。
- 回环和局域网服务器保留系统路由。仅 proxy 上游绑定接口，direct 出站及其他协议保留原行为。
- 节点域名先检查系统解析；标准 IPv4 Fake-IP 答案触发独立 AliDNS HTTPS 解析，使用同一网卡并验证 TLS。不会将 Fake-IP 直接发往物理接口，也不改写系统 DNS。直接填写 Fake-IP 字面地址会得到明确错误。
- 上游解析、找不到网卡及取消都有脱敏错误。节点认证、混淆、证书指纹及端口跳跃均保留；秘密仍只通过私有 stdio 和 DPAPI 处理。
- 探测耗尽自身的 20 秒期限后也提交错误，避免一直保持空白等待。取消、断开或被替换会话的旧结果仍被丢弃。
- 私有验收工具支持现有加密节点快照，不需要为测试再次拉取不可达的订阅，也不改写用户数据库。

## 验证与边界

Go format、vet 和完整真实核心测试通过：38 个测试通过事件、3 个显式开启的系统代理写入测试跳过。新增回归覆盖接口选择、Fake-IP 范围与混合答案、局域网保持、取消、核心接受新 DNS 配置，以及探测超时 / 旧结果处理。Flutter 静态分析通过，Dart 格式通过；本次仅修改 Dart 验收工具，应用 UI 未改动，前一轮 138 项 Flutter 测试结果保留在原记录中。

真实节点保持原证书指纹与跳跃参数，不修改原节点。原生宿主与 curl 的 IP 查询一轮为 3 / 4 成功；随后真实 Dart → Host → 核心 → Cloudflare HTTPS 验证一轮为 2 / 4 成功。其他对照也有 HTTPS 204 成功，但仍出现超时。两轮所选节点相同，成功节点并不完全相同；报告逐轮保留失败，没有挑选成功请求覆盖失败记录。对出口与地区的判断取自实际响应，不以节点名称推断；不同请求还观察到出口差异。

FlClash 关闭后订阅地址直连曾超时，因此这一轮使用原有加密节点，不把订阅拉取失败当作 Hysteria2 不受支持。机场 UDP、特定端口或目标站点的长期可用性尚未建立，不能断言剩余波动仅来自服务商或仅来自本机。加密 DNS 后备目前只覆盖标准 IPv4 Fake-IP 范围；第三方客户端共存及不同网络环境尚未全面验证。接口在重连时重选，尚无跨网卡迁移。

Release 实际选中台湾 Hysteria2 并连接，概览出现真实出口与地区，今日用量增加；后续刷新也观察到出口探测失败提示，说明单次成功不是稳定性结论。界面对台湾等尚无内置翻译 / 图标的地区目前使用返回名称与地球占位，这是现有展示缺口。

结束时已断开测试连接，两个核心监听均关闭。68 个原节点 ID、原选择、订阅分组上次选择、主题偏好及系统代理值均保持；只增加实际测试产生的流量统计。没有添加测试节点。

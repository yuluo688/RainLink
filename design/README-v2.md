## 核心产品模型

1. **节点来源**：订阅负责持续同步一批节点；手动添加负责独立保存单个节点。多个订阅与手动节点可以同时使用。
2. **统一节点库**：每个节点保留来源，支持按来源筛选、测速、收藏和直接选择。订阅更新只影响本来源，不覆盖其他订阅和手动节点。
3. **可视化代理链**：从统一节点库选择多个节点，按照“本机 → 入口 → 中间跳点 → 出口 → 目标网站”的顺序转发。末尾节点决定对外出口。没有代理链代码编辑器。
4. **连接目标与分流出站**：代理链经过测试并保存后，可在快速切换中使用，也可用于分流规则。保存代理链本身不会立即切换当前连接。

示例统一节点库共 14 个节点：主订阅 8 个、备用订阅 3 个、手动节点 3 个。HTTP 手动输入包含名称、服务器、端口和可选认证，端口校验范围为 1–65535。

示例开发代理链为“办公 HTTP（手动添加） → 东京 · 樱花 / VLESS（主订阅）”。HTTP CONNECT 入口仅能转发 TCP，因此整链标明仅支持 TCP；需要 UDP 的节点不可加入此链。整链延迟使用端到端测量，不累加单节点 Ping。

订阅更新导致节点缺失时，代理链保留原顺序并标记不可用，指出具体失效跳点。更换节点后需重新测试和保存，不静默改用其他节点或直连。

## 修改设计

设计源码位于 `plugin/`；新版模型在 `source-chain-upgrade.js`，中文文案在 `zh-CN.json`，原位本地化在 `localization.js`。

1. 修改源码后，运行 `python design/update_source.py` 合并插件代码。
2. 在 Figma 桌面应用通过“插件 → 开发 → 从清单导入插件”选择 `plugin/manifest.json`。
3. 运行 **RainLink Design Studio → 升级节点来源与可视化代理链**，原位更新已有屏幕并保留 ID。
4. “重建完整设计”会重新生成 RainLink 页面；有手动编辑时应先复制文件保留版本。

插件没有网络访问权限，不读取真实订阅或账号。简体中文为默认界面语言，品牌、协议名称、代码键名、域名和数值单位保留技术标识。

深墨色背景、克制的薄荷色强调、细边框与充足留白保持两端一致。状态同时使用文字、颜色或图标；排序提供上移 / 下移作为拖动的替代操作。
